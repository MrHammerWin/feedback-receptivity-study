# StateAct и ReflAct на тех же 40 целях TextCraft

Этот пакет дополняет повторную проверку FeedbackAgent двумя опубликованными подходами. Он использует те же 40 целей и те же исходные состояния TextCraft.

Завершены 80 эпизодов и 777 обращений к модели. Из них 77 эпизодов завершились успехом. Три эпизода остановились по лимиту обращений.

На каждый эпизод выделяли до 32 обращений и до 100 игровых действий. Моделью была `gpt-5.6-luna` с параметром рассуждения `low`.

Серия использовала подписку ChatGPT через Codex CLI 0.147.0. Платный API не использовался. Серия закрыта; её остаток не разрешает новые запуски.

Предыдущие кампании на 4416 и 2724 запусках сохранены отдельно. Новая серия не меняет их журналы и исходные результаты.

## Что именно сравнивается

StateAct использует инструкции из закреплённого авторского кода. ReflAct реализован по статье. Оба подхода работают через наши адаптеры на общей модели.

Это не запуск неизменённых авторских систем с исходными вычислительными условиями. Превосходство над мировой таблицей лидеров здесь не устанавливается.

Оба варианта получают явное пояснение открытых команд TextCraft. Оно совпадает с пояснением у `feedback_open_commands`, `grounding_only` и `raw_actor` предыдущей серии.

Порядок двух подходов чередуется внутри двух групп сложности. Каждый подход начинает первым на 20 целях. По 20 целей имеют глубину 2 и 3.

Новые эпизоды получены отдельной серией. Они не являются одновременным повтором предыдущих четырёх вариантов. Название облачной модели не гарантирует неизменные веса.

Единица сравнения здесь одна цель. В двух сериях суммарно 240 эпизодов, но разных целей остаётся 40.

Основная сравнимая таблица включает пять вариантов с одинаковым пояснением команд. Это 200 эпизодов. Старый вариант без пояснения остаётся в предыдущем пакете.

Общие файлы не скопированы повторно. Их контрольные суммы проверяются перед сборкой. Основной пакет репозитория `src/` не меняется.

Полный исполнявшийся пакет из 13 файлов имеет идентификатор:

```text
cc1a9b304f20fac8e741fed36b6891c7fd8b2617038f230aaffeace1c81d4a05
```

Этот идентификатор является контрольной суммой SHA256. Он вычисляется по именам и содержимому файлов. Он не является цифровой подписью.

Сторонние инструкции и примеры не включены в GitHub-пакет. Условия их использования описаны в [THIRD_PARTY.md](../../THIRD_PARTY.md).

Полные ответы модели, журналы подписки и приватные прежние выгрузки также не включены. Открытая проверка не доказывает происхождение этих первичных данных.

## Проверка чисел без модели

Откройте корень репозитория с этим пакетом. Выполните:

```sh
python -B retests/textcraft_baselines/verify_numeric.py
```

Команда проверяет сохранённые числовые файлы. Она не входит в аккаунт, не загружает сторонние инструкции и не вызывает модель.

Она сравнивает два новых подхода с тремя прежними вариантами, получившими то же пояснение. Для парной статистики используется существующий `analysis/paired_statistics.py`.

Открытая сверка использует три прежних варианта с общим пояснением. Она повторяет основное сравнение при 32 обращениях.

Старый публичный CSV не содержит исходы при 16 обращениях и подробные токены. Эти прежние показатели остаются за границей открытого пересчёта.

Для двух новых подходов CSV содержит полный числовой учёт токенов и времени. Кешированные входные токены входят в общий вход и повторно не прибавляются.

Время включает ожидание CLI и сети. Оно не является чистым временем вычисления модели.

Каждая пара сопоставляется по идентификатору цели. Повторы строк и пропущенные цели должны приводить к отказу проверки.

Для отдельно сохранённого числового файла тех же 80 эпизодов можно указать другой CSV:

```sh
python -B retests/textcraft_baselines/verify_numeric.py --csv local/own-baselines.csv
```

В этом режиме программа проверяет структуру и выводит сравнения нового CSV. Она не требует совпадения новых результатов с опубликованными оценками.

Новый CSV должен сохранять те же цели, варианты и названия числовых столбцов. Тексты ответов и игровые команды для сравнения не нужны.

## Подготовка новой реплики

Для новой реплики требуется отдельное разрешение владельца подписки. Закрытые кампании и их остатки использовать нельзя.

Нужны Linux или WSL2, CPython 3.12 и Codex CLI 0.147.0. Нативный Windows не поддерживает используемый Unix-модуль `fcntl`.

Установите записанные прямые зависимости из предыдущего пакета:

```sh
python3.12 -m venv .venv-baselines
. .venv-baselines/bin/activate
python -m pip install -r retests/textcraft/requirements-retest.txt
```

Подготовьте вход через собственную подписку ChatGPT:

```sh
npm install -g @openai/codex@0.147.0
codex login
codex login status
```

Историческая модель `gpt-5.6-luna` должна быть доступна аккаунту. Если она недоступна, остановитесь. Другая модель означает отдельное исследование.

## Явная загрузка входных материалов

Выберите локальный каталог вне публичного пакета. Следующая команда загружает закреплённые материалы, но не вызывает модель:

```sh
export FEEDBACK_BASELINE_ASSETS="$PWD/local/baseline-inputs"
python retests/textcraft_baselines/source_delta/asset_download.py --cache-dir "$FEEDBACK_BASELINE_ASSETS"
```

Загрузчик проверяет источники и все 12 полученных файлов. Он извлекает разрешённые статические выражения и не исполняет сторонний Python.

Сохраните `FEEDBACK_BASELINE_ASSETS` в том же терминале для подготовки и запуска. Не коммитьте этот каталог и не копируйте его в публичную поставку.

Изменение исходных материалов приводит к отказу проверки. Не заменяйте ожидаемые контрольные суммы ради продолжения.

## Отдельное разрешение и подготовка

Задайте порядок хеширования до запуска Python:

```sh
export PYTHONHASHSEED=0
```

После нового разрешения владельца ресурсов выполните подготовку. Используйте собственный новый идентификатор с префиксом `replica-`:

```sh
python -B retests/textcraft_baselines/prepare_replica.py --directory local/baselines-replica-01 --campaign replica-baselines-01 --max-launches 2560 --i-authorize-subscription-use
```

Подготовка не вызывает модель. Она собирает пакет из девяти общих и четырёх новых файлов. Сначала она сверяет его с исполненным пакетом.

Затем она меняет две строки в изолированной копии `experiment.py`. Первая задаёт новый идентификатор кампании. Вторая связывает новую реплику с открытой сокращённой проверкой целей.

Приватная проверка целей не распространяется. Поэтому новая копия использует контрольную сумму открытого файла. Она не выдаётся за неизменённый приватный оригинал.

Инструкции модели, порядок целей, чередование подходов и лимит эпизода сохраняются. Новый идентификатор исходников записывается в `preparation.json`.

Подготовка проверяет 80 исходных наблюдений и закреплённые материалы подходов. Несовпадение останавливает её до создания разрешения подписки.

При таком отказе может остаться неполная локальная папка подготовки. Сначала выясните причину. Не меняйте контрольные суммы и не перезаписывайте прежние журналы.

TextCraft может менять отвлекающие рецепты между средами исполнения. Поэтому совпадение цели и seed не гарантирует совпадения исходного наблюдения.

Предел 2560 равен 40 целям, двум подходам и максимум 32 обращениям. Неудачные попытки также расходуют новый предел.

## Явный запуск модели

Используется общий скрипт из предыдущего пакета:

```sh
bash retests/textcraft/run_replica.sh local/baselines-replica-01 --start
```

Эта команда начинает реальные обращения. Она проверяет подготовленные исходники и конфигурацию. Блокировка `flock` запрещает параллельный запуск той же кампании.

Программа получает новые ответы. Она не переносит ответы предыдущих серий и не исправляет команды эталонными действиями.

При транспортном отказе новые старты останавливаются. Незавершённый эпизод не повторяется скрыто. Причину остановки нужно разобрать отдельно.

## Локальные выходные файлы

Новые файлы находятся внутри `local/baselines-replica-01/`. Они используют ту же структуру, что описана в [инструкции TextCraft-повтора](../textcraft/README_RU.md).

`allowance.attempts.jsonl` хранит новые попытки. `results/episodes/` хранит эпизоды. `results/model_calls.jsonl` хранит ответы и телеметрию.

`results/run.json` фиксирует версии, входы и исходники. `results/source_snapshot.zip` сохраняет фактически использованный код. `checkpoint.json` ограничивает новые старты.

Эти локальные файлы могут содержать диалоги и пути компьютера. Они не должны автоматически попадать в публичный репозиторий.

После анализа публикуйте только проверенные числовые поля и допустимые идентификаторы. Полные ответы не нужны для повторного пересчёта опубликованной статистики.

## Границы воспроизводимости

Открытые CSV позволяют проверить арифметику и парные сравнения. Они не заменяют первичные диалоги и серверные квитанции.

Будущая реплика может получить другие ответы облачной модели. Подготовка не гарантирует её доступность или завершение всех вызовов.

Код и инструкция подготовлены с существенной помощью ИИ. Автоматические проверки не являются внешним научным рецензированием.
