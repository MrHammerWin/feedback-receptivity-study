# Как установить и запустить FeedbackAgent

Эта инструкция разделяет три задачи: увидеть работу программы на подготовленных ответах, проверить опубликованные числа и провести новый опыт с языковой моделью. Первые две задачи не обращаются к модели. Третья расходует отдельно разрешённый лимит владельца подписки и не нужна для чтения результатов курсовой.

Все исследовательские кампании закрыты. Для новых обращений требуется отдельное разрешение владельца подписки. Журналы закрытых кампаний и их лимиты сохраняются. В описанных ниже конфигурациях платный API отключён.

## Что уже есть в репозитории

| Где искать | Что находится внутри |
| --- | --- |
| `src/crmn_agent/feedback_control.py` | Полный контроллер: исполнитель, критик, две проверки цитат и выбор способа пересмотра |
| `src/crmn_agent/grounding.py` | Выбор буквального фрагмента наблюдения для проверок |
| `src/crmn_agent/environments.py` | Связь с игровыми средами ALFWorld и TextCraft |
| `src/crmn_agent/qa_study.py` | Подготовка и выполнение контролируемого опыта на вопросах |
| `src/crmn_agent/published_baselines.py` | Адаптеры StateAct и ReflAct для сравнения на общей модели |
| `src/crmn_agent/codex_provider.py` | Обращение к Codex CLI, учёт попыток и контроль бюджета |
| `scripts/` | Подготовка данных, проверки результатов и вспомогательные команды |
| `source_data/` | Опубликованные числовые результаты и идентификаторы задач |
| `retests/textcraft/` | Код опыта на 40 целях TextCraft для вариантов FeedbackAgent |
| `retests/textcraft_baselines/` | Код StateAct и ReflAct на тех же целях, общая проверка пяти вариантов |
| `analysis/` и `figures/coursework/` | Код анализа и четыре рисунка текущей курсовой |
| `tests/` | Существующие автоматические проверки на подготовленных ответах |

Техническое имя пакета `crmn_agent` сохранено исторически. Исследуемая система называется FeedbackAgent. Она не воспроизводит исходную нейронаучную CRMN-модель. Собственный код опубликован по MIT; условия сторонних данных и материалов действуют отдельно. Подробности находятся в [THIRD_PARTY.md](../THIRD_PARTY.md).

Чужие тексты вопросов, промпты бейзлайнов и полные модельные диалоги намеренно не включены. Для новых опытов данные и входные материалы загружаются отдельно с проверкой закреплённых хешей. Отсутствие этих материалов в GitHub не означает отсутствие кода агента.

## Как выбрать способ запуска

| Что вы хотите сделать | Нужна модель | Где выполнять |
| --- | --- | --- |
| Увидеть последовательность действий на подготовленном примере | Нет | Windows PowerShell, Linux или macOS |
| Пересчитать опубликованные числа и построить рисунки | Нет | Windows PowerShell, Linux или macOS |
| Запустить полный набор существующих тестов | Нет | Linux, macOS или WSL2 |
| Получить новые ответы модели в QA или играх | Да, по отдельному разрешению | Linux, macOS или WSL2 |

Для реальных запусков из Windows используйте Linux-среду WSL2. В текущем `codex_provider.py` используется Unix-модуль `fcntl` для блокировки общего журнала. Поэтому этот backend и часть полного набора тестов не работают в нативном Windows Python. Подмена или удаление блокировки ради запуска нарушит защиту лимита. Поддержка нативного Windows для этого backend в данной версии не реализована.

## Windows PowerShell: пример без модели

Нужны Git и Python 3.12. Сам пакет допускает Python 3.11 и новее, но прямые версии библиотек из `requirements-study.txt` относятся к Python 3.12 и новее. Этот файл не является полным снимком всех зависимостей и операционной системы.

Откройте PowerShell в папке для проекта:

```powershell
git clone --branch study-materials https://github.com/MrHammerWin/feedback-receptivity-study.git
cd feedback-receptivity-study
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -e ".[reports]"
& .\.venv\Scripts\python.exe -B examples/offline_demo.py
```

Если проект уже скачан, начинайте с его корня и не выполняйте повторное клонирование поверх существующей папки. Вызов Python через полный относительный путь к `.venv` позволяет обойтись без активации окружения и изменения политики PowerShell. Установка зависимостей обращается в сеть; сам пример модель не вызывает.

Пример должен вывести действие `open box`, число подготовленных вызовов `5`, маршрут `critique` и признак `is_real_llm: False`. Программа имитирует ответы исполнителя, критика и проверок. Это проверка последовательности работы кода, а не результат настоящей модели или бенчмарка.

Пересчитать опубликованные числа можно отдельно:

```powershell
& .\.venv\Scripts\python.exe -B scripts/verify_scored_data.py --source-data source_data --json
& .\.venv\Scripts\python.exe -B retests/textcraft_baselines/verify_numeric.py
```

Первая команда проверяет сохранённые результаты на вопросах и в исходном игровом опыте. Для текущей статьи из этого опыта используется ALFWorld. Вторая команда проверяет итоговое сравнение пяти вариантов на 40 целях TextCraft при лимите 32 вызова. Обе команды читают числовые данные. Приватные диалоги в них не используются.

Полный `pytest` из нативного Windows здесь не предлагается: тесты, импортирующие subscription backend, требуют `fcntl`. Для полного набора используйте следующую Linux-инструкцию.

## Linux, macOS или WSL2: установка и локальные проверки

В WSL2 все следующие команды вводятся внутри Linux-терминала. Python, Node.js, Codex CLI и вход в аккаунт должны быть доступны именно в этой среде. Наличие Windows-приложения Codex само по себе этого не гарантирует.

```sh
git clone --branch study-materials https://github.com/MrHammerWin/feedback-receptivity-study.git
cd feedback-receptivity-study
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[dev,reports]'
python -B examples/offline_demo.py
python -B -m pytest -q -p no:cacheprovider
python -B tools/check_public_tree.py .
python -B scripts/verify_scored_data.py --source-data source_data --json
python -B retests/textcraft_baselines/verify_numeric.py
```

Если Python 3.12 в системе называется иначе, используйте соответствующий исполняемый файл. Тесты используют подготовленные ответы и блокируют сетевые соединения. Установка пакетов требует сети. Проверка `check_public_tree.py` предназначена для чистого публикуемого дерева: приватные данные, журналы и заново построенные бинарные рисунки внутри него вызывают отказ, даже если Git их игнорирует.

## Как открыть и пересчитать рисунки

Четыре готовых рисунка лежат в [figures/coursework](../figures/coursework). Команда ниже заново строит две игровые диаграммы из опубликованных чисел. Запустите её из корня проекта после установки `reports`:

```sh
python -B analysis/plot_coursework_games.py --out rebuilt_figures
```

В PowerShell вместо `python` укажите `& .\.venv\Scripts\python.exe`. В папке `rebuilt_figures/` появятся `game-success.svg` и `game-calls.svg`. Можно указать папку за пределами репозитория. Для `check_public_tree.py` используйте чистую копию. [Источники данных и исходные рисунки](../analysis/README.md)

## Новые ответы модели: сначала отдельное разрешение

Остановитесь на этом разделе, если нужно только посмотреть код или проверить статью. Следующие команды описывают новый опыт владельца подписки. Они не являются разрешением продолжить закрытую кампанию курсовой. Доступность модели и ресурсный лимит согласуются отдельно. Старый журнал не удаляется, не уменьшается и не переносится в новую кампанию ради восстановления квоты.

Для нового опыта нужны:

1. Linux, macOS или WSL2 с подготовленным Python-окружением.
2. Codex CLI, вошедший через собственную подписку ChatGPT. API-ключ для этого backend не используется.
3. Доступная этому аккаунту модель и новый идентификатор кампании.
4. Явный лимит попыток и данные выбранной задачи.

В исследовании записана версия CLI 0.147.0. Команды настройки из исходного протокола:

```sh
npm install -g @openai/codex@0.147.0
codex login
codex login status
python -m pip install -e '.[benchmarks,qa,reports]'
```

Выберите вход через ChatGPT. Подписка не означает наличие API-кредитов и не гарантирует доступность исторического `gpt-5.6-luna`. Другая модель означает отдельную репликацию, её результаты нельзя приписывать исходной серии.

После отдельного согласования небольшого опыта создайте новую локальную конфигурацию, заменив `YOUR_AVAILABLE_MODEL` на доступную модель:

```sh
python -m crmn_agent.public_authorization --directory local/demo --campaign local-demo --max-launches 50 --model YOUR_AVAILABLE_MODEL --resource-profile smoke --i-authorize-subscription-use
```

Эта команда не вызывает модель. Она создаёт `local/demo/provider.json` и `local/demo/allowance.json`; существующие конфигурации, разрешения и журналы она не перезаписывает. Флаг согласия должен соответствовать реальному решению владельца подписки. В конфигурации выставляется `allow_paid: false`.

Действуют два разных ограничения. `--max-launches 50` задаёт общий сохраняемый предел новых попыток. Профиль `smoke` дополнительно ограничивает один процесс: 1000 логических вызовов и 1 млн входных и выходных токенов. Логический вызов может переиспользовать сохранённый ответ и тогда не создаёт новую попытку CLI. Неудачная новая попытка всё равно расходует общий предел. Параметр `cap` у запроса не является строгим пределом выходных токенов Codex CLI.

## Небольшой игровой опыт в TextCraft

Этот учебный запуск использует общий пакет `src/`. Для опыта с 40 целями и общим пояснением команд используйте инструкции из раздела ниже.

Сначала подготовьте задачу. Эта команда создаёт среду и фиксирует её фактический вход, но модель не вызывает:

```sh
python scripts/prepare_smoke.py --provider-config local/demo/provider.json --benchmark textcraft --seed 0 --out local/demo/native.json
```

Новый запуск модели начинается только следующей командой. Выполняйте её лишь в пределах отдельно согласованного нового опыта:

```sh
python -m crmn_agent.experiment local/demo/native.json
```

Сравниваются исходный исполнитель и FeedbackAgent. Общих 50 попыток может не хватить на завершение обоих эпизодов. Остановка по лимиту не превращает незавершённый пример в итоговый бенчмарк и не разрешает автоматически выдать новый лимит.

Конфигурация находится в `local/demo/native.json`, зафиксированная задача в `local/demo/native.manifest.json`, результаты в `local/demo/native-private-results/`. Внутри результатов сохраняются `run.json`, `model_calls.jsonl`, снимок исходного кода и файлы эпизодов. Журнал зарезервированных попыток называется `local/demo/allowance.attempts.jsonl`. Кеш и временные изолированные каталоги задаются в `provider.json`. Эти файлы могут содержать сырые данные и пути компьютера; они остаются локальными.

Для ALFWorld сначала отдельно получите официальные текстовые игры, затем подготовьте другую конфигурацию:

```sh
python scripts/prepare_alfworld.py
python scripts/prepare_smoke.py --provider-config local/demo/provider.json --benchmark alfworld --seed 0 --out local/demo/alfworld.json
```

Загрузка игровых файлов не вызывает модель. Условия использования данных действуют отдельно. Подготовка второй конфигурации не увеличивает общий лимит из того же `provider.json`.

## Небольшой опыт на вопросе

Сначала скачайте закреплённые данные и создайте локальный список вопросов:

```sh
python scripts/fetch_qa_data.py --out local/private_cache/wafer.parquet
python -m crmn_agent.qa_study prepare --data local/private_cache/wafer.parquet --out local/demo/qa-manifest.json
```

Загрузчик проверяет версию и SHA256. В публичном `source_data/qa_manifest.json` сохранены только идентификаторы и хеши; его нельзя передать вместо полного локального манифеста.

Следующая команда вызывает модель на одном вопросе разработки, проверяя оба условия совета и пять политик:

```sh
python -m crmn_agent.qa_study run --config local/demo/provider.json --data local/private_cache/wafer.parquet --manifest local/demo/qa-manifest.json --out local/demo/qa-run --split dev --limit 1
```

Она расходует тот же лимит `local/demo`, если используется та же конфигурация. В `local/demo/qa-run/` сохраняются `run_metadata.json`, `outcomes.jsonl` и `model_calls.jsonl`; тексты вопросов и полные ответы не публикуются. Это пример запуска на одном вопросе, а не воспроизведение основной выборки из 120 вопросов.

## Проверка на тех же задачах с новыми ответами

Для текущего сравнения TextCraft используйте два пакета с одинаковыми задачами и общим пояснением команд:

- [StateAct и ReflAct](../retests/textcraft_baselines/README_RU.md). Пакет проверяет опубликованные числа всех пяти вариантов. Его команда новой кампании запускает два варианта. Верхняя оценка для них равна 40 × 2 × 32 = 2560 обращений.
- [FeedbackAgent, вариант без двух проб и вариант без критика](../retests/textcraft/README_RU.md). Исходный пакет запускает четыре варианта. В него также входит контрольный вариант FeedbackAgent без пояснения команд. Он не входит в итоговую таблицу пяти вариантов.

Для полного QA и опубликованных задач ALFWorld используйте [команды исходного протокола](../README.md#use-the-recorded-task-selection). Они также описывают архивные 8 задач TextCraft. Для QA предусмотрено 1560 логических вызовов. Один блок ALFWorld из пяти вариантов может потребовать до 320 вызовов. Профиль `recorded-study` задаёт внутренние пределы процесса. Общий лимит новых запусков устанавливается отдельно.

Для игровых адаптеров StateAct и ReflAct входные материалы получают явно командой `python -m crmn_agent.asset_download`. Они не включены в собственный MIT-код. Для закреплённого игрового протокола `PYTHONHASHSEED=0` задаётся до старта Python:

```sh
export PYTHONHASHSEED=0
```

В TextCraft одинаковая цель и seed могут давать разные отвлекающие рецепты в разных процессах. Строгая подготовка останавливается на несовпадении входов. Явный режим `--fresh-replication` фиксирует новые входы для тех же целей и не обещает исходных рецептов или тех же оценок. Подготовка конфигураций не запускает их автоматически. Новые результаты хранятся отдельно от исходных данных статьи.

## Если команда остановилась

| Сообщение или ситуация | Что это означает и как действовать |
| --- | --- |
| `No module named fcntl` | Запущен Unix-backend из нативного Windows. Перейдите в WSL2/Linux/macOS; не удаляйте блокировку бюджета |
| Уже существуют `provider.json`, разрешение или журнал | Программа защищает прежнее состояние. Для отдельного согласованного опыта нужен новый каталог и идентификатор кампании |
| Исчерпан лимит попыток или сработал checkpoint | Новые старты запрещены. Сохраните журнал; продолжение требует отдельного решения владельца ресурсов |
| Транспортный отказ, ограничение сервиса или ошибка формата | Сохраните запись и причину. Неудачная попытка не возвращается в бюджет; скрытого бесплатного повтора нет |
| Не совпал хеш данных, промптов или рецептов | Вход отличается от закреплённого. Не исправляйте ожидаемый хеш ради продолжения; сначала выясните происхождение отличия |
| В примере `is_real_llm` равно `False` | Это ожидаемый подготовленный пример, модель не участвовала |

Проверки и демонстрация не доказывают научную эффективность метода. В итоговой серии преимущество FeedbackAgent не подтверждено; адаптации StateAct и ReflAct решили больше игровых задач при меньших средних затратах. Инструкция помогает воспроизвести код и анализ, сохраняя эти ограничения и раскрытие существенной помощи ИИ.
